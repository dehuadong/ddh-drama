# 小说改编项目校验与质量审查

本文件只描述实际小说改编项目中可使用的检查方式，不包含技能仓库开发、维护或发布检查。

## 项目产物基础检查

只检查当前改编项目中的项目配置和创作产物，例如：
- 项目配置 YAML 的可解析性、必需字段及 Schema。
- 项目文档的必要内容标记。
- 人物、事件、伏笔、改编决策、审查问题和场景等稳定 ID 的格式与重复定义。
- 结构化记录之间的引用完整性（在相应索引数据已建立时）。

运行：

```bash
pip install -r requirements.txt
python tools/validate_project.py path/to/adaptation-project
```

该检查不检查技能仓库的 SKILL.md、Frontmatter、references、templates、开发脚本或 CI 配置。

## 改编质量审查

由改编工作流的审查阶段执行，检查：
- 原著核心事件、因果关系与情绪价值是否保留或经批准地转换。
- 人物动机、行为逻辑、关系变化和人物弧光是否一致。
- 删改、合并、重排、新增剧情是否有原著依据、戏剧功能、影响和审批记录。
- 剧集是否产生有效局势变化，而非机械切章。
- 场景是否具备目标、阻力、行动和状态变化。
- 时间、地点、人物状态、信息、道具、伤势及伏笔兑现是否连续。
- 剧本是否具备可表演、可拍摄的表达。

脚本只能检查确定性约束和辅助定位，不能替代语义判断。质量结论应区分客观错误、创作风险和审美建议。

## 结构化数据与 Markdown 的权威关系

- YAML/JSON 保存适合机器校验和跨文件引用的字段；Markdown 保存解释性分析、创作论证、人物弧光、事件过程、场景和剧本正文。
- 同一字段只设一个权威来源，禁止要求用户重复维护两份同义数据。
- 项目配置 YAML 是项目参数的权威来源；叙述内容以对应 Markdown 文档为权威来源。
- Schema 是字段契约，不意味着每个项目都必须额外维护一份重复 JSON。机器索引优先从 Markdown 的稳定 ID 和明确元数据提取。
