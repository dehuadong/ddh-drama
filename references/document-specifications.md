# 文档规范
## 通用
Markdown UTF-8，配置 YAML。文档标明项目、版本、状态、更新时间、资料依据和覆盖范围。区分事实、推断、建议、待确认；避免重复维护权威信息。
## 权威顺序
用户最新明确决定 > 已批准项目配置/设定 > 已批准改编方案/故事结构 > 已批准分集大纲 > 剧本草稿 > AI建议/未审批草案。发现冲突应提出，不得静默覆盖。
## 状态
DRAFT草稿；REVIEW待审；APPROVED用户已确认；FINAL正式定稿；SUPERSEDED已被替代。生成完成不等于审批通过。
## 推荐目录
```
项目/
├── project-config.yaml
├── 01-原著分析/
├── 02-改编方案/
├── 03-故事重构/
├── 04-剧集规划/
├── 05-剧本/
└── 06-审查/
```
## 长篇分批
每批更新覆盖记录、人物/事件/伏笔索引、时间线和未决问题；全书结论说明覆盖范围。
## 稳定ID
人物C001；事件E001；伏笔F001；决策D001；审查R001；场景S01-001。已使用ID不因排序变化而重编号，删除项保留状态，不复用。
## 修改传播
人物身份/关系变化检查大纲、分集、剧本；事件顺序变化检查时间线、伏笔、连续性；结局变化检查结构、弧光、伏笔；集数变化检查阶段、分集、剧本编号。
